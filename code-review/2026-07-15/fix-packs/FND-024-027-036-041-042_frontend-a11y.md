# Fix Pack — FND-024 / FND-027 / FND-036 / FND-041 / FND-042: Accessibility & frontend robustness

**Severity:** Medium (FND-024, -027, -036), Low (FND-041, -042) · **Domain:** Frontend/UX/a11y (WCAG 2.2 AA) · **Effort:** M
All in `frontend/`.

## Context
`[repository root]`, React 18 + TS. The design already respects `:focus-visible`
(`frontend/src/index.css:160`) and `prefers-reduced-motion`, so this is filling gaps, not a rebuild.

---

## FND-024 — Edit-user modal is not an accessible dialog
**Evidence:** `frontend/src/components/UserEditModal.tsx:110` is a plain `<div className="modal">` — no
`role="dialog"`, no `aria-modal="true"`, no focus trap, no Escape-to-close, no focus-on-open / restore-on-close.
**Fix:** add `role="dialog" aria-modal="true"` + an `aria-labelledby` pointing at the "EDIT USER" heading;
trap focus within the panel; move focus to the first control (or the close button) on open and restore focus
to the triggering "Edit" button on close; wire `Escape` → `onClose`. Consider extracting a reusable
`<Modal>` (the login/other panels can adopt it later). Keep the click-outside-to-close behaviour.

## FND-027 — Silent sign-in failure + no WS reconnect
**Evidence:** `frontend/src/pages/LoginPage.tsx:40-67` — if the GSI script never loads, the poll loop gives
up after 50 tries with no visible state. `frontend/src/presence/PresenceContext.tsx:86` — the presence WS
never reconnects after a drop (permanent degrade to 20s polling).
**Fix:** show an explicit error + "Retry" when GSI fails to appear (reuse the existing `configFailed` error
pattern in the same file). Add bounded exponential-backoff reconnect to the presence WebSocket (cap the
delay; stop on unmount / logout).

## FND-036 — Accessibility minutiae (batch)
**Evidence & fixes:**
- **Custom accent has no contrast floor** (`frontend/src/components/AppearancePanel.tsx:207`,
  `frontend/src/util/theme.ts` `applyAccent`). Add a contrast check (against the base background) that
  warns or clamps when a chosen accent falls below ~3:1 for UI / ~4.5:1 for text; at minimum warn in the UI.
- **`--muted` below AA** on the `panel-2` surface (`frontend/src/index.css:16` token; used for table/section
  headers). Darken/lighten `--muted` (both themes) until it meets 4.5:1 on `--panel2`.
- **Unlabeled controls** — select-all + per-row checkboxes (`frontend/src/pages/AdminUsersPage.tsx:238,265`)
  and the modal's banner dismiss button (`UserEditModal.tsx:147`) lack accessible names. Add `aria-label`
  (e.g. "Select all users", "Select {email}", "Dismiss"). (The AdminUsersPage banner dismiss already has one
  at :159 — mirror it.)
- **No focus management on route change** and the color-input focus ring is effectively invisible
  (`AppShell.tsx:104`, and `index.css:256` `.field-input:focus{outline:none}` overrides the global
  `:focus-visible` outline because the global rule uses zero-specificity `:where()`). Move focus to the main
  heading / a skip target on navigation, and ensure text inputs keep a visible focus indicator (don't let
  `.field-input:focus{outline:none}` remove it for keyboard users — scope it to `:focus:not(:focus-visible)`).

## FND-041 — Stale client permissions
**Evidence:** `frontend/src/auth/AuthContext.tsx:20-34` fetches the user once at load and never refreshes;
nav + `RequirePermission` gate on stale data until reload. (Server still enforces per request, so this is
UX/defense-in-depth only.)
**Fix:** re-fetch `/api/auth/me` on window focus and/or a periodic interval, updating context; keep the
server as the source of truth.

## FND-042 — e2e is smoke-only
**Evidence:** `frontend/e2e/access-control.spec.ts` asserts render/redirect only; no test drives a mutation.
**Fix:** add an e2e that signs in as admin, opens the edit modal, changes a profile field, saves, and
asserts the change persisted (reload + verify), exercising the real PATCH round-trip.

## Constraints — do NOT change
- Keep the DATASTREAM terminal aesthetic and the existing reduced-motion / calm-mode behaviour.
- Keep server-side authz as the source of truth (client gates are UX only).
- Don't regress the passing vitest suite or the two existing e2e tests.

## Acceptance criteria
- Modal: keyboard-only user can open, tab within (focus trapped), Escape to close, focus returns to trigger;
  axe/lighthouse shows no dialog-role violation.
- `--muted` on `panel-2` and any clamped accent meet WCAG 1.4.3 (4.5:1 text).
- All interactive controls have accessible names (axe: no "name" violations on the users page + modal).
- GSI-load failure shows an error+retry; presence WS reconnects after a simulated drop.
- New mutation e2e passes; `cd frontend && npm run lint && npm run test && npm run build` green.
