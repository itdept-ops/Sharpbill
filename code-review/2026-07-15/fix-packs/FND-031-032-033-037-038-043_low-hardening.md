# Fix Pack — Low-severity hardening batch (FND-031/032/033/037/038/043)

**Severity:** Low · **Effort:** XS–S each · Pick up opportunistically; none is urgent. Several become moot
once rate-limiting/replay move to shared state (FND-023) or a trusted proxy is added (FND-009).

## Context
`C:\dev\kingfisher-crm`, FastAPI backend. These are defense-in-depth / hygiene items; each is independently
shippable and low-risk.

---

### FND-031 — Crypto niceties
- **Replay window vs verifier leeway.** `backend/app/auth/google.py:39` / `microsoft.py:52` size the
  replay TTL as `exp - now`, but the verifier accepts the token for `leeway`/`clock_skew` (30s) *past* exp
  (`google.py:24`, `microsoft.py:26`). A token can be re-accepted in that 30s gap. Fix: extend the replay
  TTL by the same leeway (`exp - now + leeway`).
- **Google cert caching.** `backend/app/auth/google.py:11,20` builds a fresh transport and re-fetches
  Google certs on every login, unlike the cached Microsoft `PyJWKClient` (`microsoft.py:12`). Fix: cache the
  Google certs (the `google-auth` transport supports caching; reuse a module-level cached client).
- **No OIDC nonce; process-local replay.** `backend/app/auth/replay.py` is per-process and there's no nonce
  binding (already documented as pending live-OAuth). Fix: add provider-nonce validation when the live OAuth
  client flow lands; move the replay set to shared storage (Redis) alongside FND-023.
- **Secret entropy.** `backend/app/config.py:33-38` validates the JWT secret for length (≥32) only, not
  entropy. Fix: optionally add a Shannon-entropy or charset-diversity check to reject low-entropy 32-char
  secrets.

### FND-032 — Schema hygiene
- **`extra="forbid"` missing on mutating schemas.** Only `UiPrefs` sets it (`backend/app/schemas/user.py:121`).
  `ProfileUpdate`, `RoleAssignRequest`, `StatusUpdateRequest`, `PermissionGrantRequest`,
  `SiteSettingsUpdate` (`schemas/settings.py`), `LocationUpdate` (`schemas/auth.py`) don't. This is **not** a
  mass-assignment vuln (Pydantic *ignores* unknown fields; they aren't set on the model), but adding
  `model_config = ConfigDict(extra="forbid")` turns silent typos into 422s. Fix: add it to the mutating
  request schemas.
- **Unbounded `permission_keys` lists.** `schemas/user.py:105` (`PermissionGrantRequest`) and the role
  schemas have no `max_length`, unlike `BulkActionRequest.ids` (`:109`). Fix: add a sane `max_length`.
- **Subject-id disclosure.** `UserOut.identities[].subject` (`schemas/user.py:73-76`) exposes the immutable
  OAuth `sub`/`oid` to any `users.read` holder. Low sensitivity, but consider restricting it to
  `users.manage`/self if not needed in the directory.

### FND-037 — Error handling
- **422 body reflection.** `backend/app/errors.py:27-38` returns `errors: jsonable_encoder(exc.errors())`,
  which includes the offending `input` value, and deviates from the `{code,message}` envelope by adding an
  `errors` array. Fix: either drop the `input`/raw body from the reflected errors, or document the `errors`
  extension as intentional and ensure it never echoes sensitive fields.
- **500s not audited.** An unhandled exception propagates past the `_request_log` middleware
  (`backend/app/main.py:51-60`) before `record_request` runs, so 500s aren't persisted. Fix: record the
  request in a `finally`/exception path so error responses are also logged (guard against recursion).

### FND-038 — Lost-update on concurrent admin edits
- `set_user_permissions` (PUT-replace, `backend/app/routers/users.py:283-310`), `update_role`, and
  `update_status` have no optimistic-concurrency guard; two concurrent admin edits silently drop one —
  including a lost revocation (fail-open). Fix: add a `version`/`updated_at` optimistic-lock check (reject on
  stale version) on these mutations if concurrent admin editing is a real scenario.

### FND-043 — Fail-open APP_ENV default
- `backend/app/config.py:10` `app_env: Literal["local","production"] = "local"` defaults to the value that
  enables the dev-auth gate and relaxes the secure-cookie invariant. Fix: either default to `"production"`
  (fail-safe) or make `APP_ENV` required (no default), so a missing/typo'd env can't silently select the
  less-safe mode. Coordinate with `conftest.py` / CI which set `APP_ENV=local` explicitly (they already do).

## Constraints — do NOT change
- Keep the `{code,message}` envelope contract for existing consumers (frontend `client.ts` reads
  `detail.code`/`detail.message`).
- Don't break the test harness, which sets `APP_ENV=local` and `DEV_AUTH_ENABLED=true` explicitly.
- Reuse existing helpers; keep changes minimal and independently revertible.

## Acceptance criteria
- Each sub-fix has (or is covered by) a test where practical (e.g. unknown-field → 422; replay rejected
  within leeway window; APP_ENV default behaviour).
- `docker compose exec api pytest` green; `ruff check . && ruff format --check .` clean.
